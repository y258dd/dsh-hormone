# 设计说明

> 插件怎么来的、为什么这么设计。实现细节见 README 与 `lib/`。

## 背景

目标是给 DSH 助手加一套「激素机制」：一组连续变化的内分泌状态（压力、精力、爽度），随交互事件涨落、随时间衰减，并且真的改变行为，而不是隔一会儿摇个骰子决定「今天心情如何」。

市面上所谓的「活人味」插件大多靠定时器 + 写死的提示词，情绪只是标签。这套东西的分水岭在于：**状态是否跨轮持续、是否由事件因果驱动、是否真的影响输出**。

## 结论：做插件，不改提示词

写成一份静态文本不行：读的时候状态是死的，也没有东西能更新它。

插件 API 与 `dsh-memory-lite` 同源：

| 能力 | 接口 |
|---|---|
| 订阅每轮事件 | `ctx.on('session/event', (session, event) => …)` |
| 往系统提示注入 | `ctx.systemPrompt.context({ name, order, text })` |
| 依赖声明 | `export const inject = ['systemPrompt']` |
| 清理 | `ctx.effect(() => () => …)` |

事件类型（实测可用）：`user/message`、`assistant/message`、`tool/call`、`tool/result`。

## 状态模型（0.3.0 起四个）

| 变量 | 含义 | 范围 | 半衰期 |
|---|---|---|---|
| `cortisol` | 压力 | 0–1 | 3 小时（开心时最短 65%） |
| `energy` | 可用预算/精力 | 0–1 | 按天重置 |
| `dopamine` | 爽度 | 0–1 | 40 分钟 |
| `boredom` | 无聊 | 0–1 | 平静 25 分钟后开始涨，涨得慢（5 小时半衰期量级，向 1 靠） |

`boredom` 的时间基准是 `state.lastUserAt`（最后一次真人发消息），不是 `lastWorkAt`——闷不闷取决于有没有人理它，跟干没干活无关。

`bond`（亲密度）暂缓：变化太慢，跑一周看不出差别，先不加。

## 更新规则

```
新值 = clamp(旧值 × 0.5^(Δt / 半衰期) + Σ增量, 0, 1)
```

| 事件 | 效果 |
|---|---|
| 工具报错 | cortisol +0.08 |
| 连续 3 次失败 | cortisol +0.15 |
| 任务成功收尾 | dopamine +0.35，cortisol −0.20，boredom −0.25 |
| 被夸/被谢 | dopamine +0.40，boredom −0.10 |
| 被批评/被纠正 | cortisol +0.12 |
| 真人说话 | boredom −0.30，并把 `lastUserAt` 重置为现在 |
| 每轮结束（这轮调过工具） | energy −= 本轮 token ÷ 日预算 × `energyCostScale()` |
| 距上次干活超过 30 分钟 | energy 缓慢回升，闲聊不推迟 |
| 深夜 23:00–06:00 | energy 基线压低 |

## 情绪耦合（0.3.0 新增）

四个数不是各算各的，`COUPLING` 里四个系数：

| 耦合 | 实现 | 系数 | 极端值 |
|---|---|---|---|
| 爽度 → 精力扣减 | `energyCostScale` 里的 `−0.5 × dopamine` | `joyCost = 0.5` | 满爽度一活儿省 50% |
| 压力 → 精力扣减 | `energyCostScale` 里的 `+0.8 × cortisol` | `stressCost = 0.8` | 满压力一活儿多花 80% |
| 爽度 → 压力消散 | 有效半衰期 `×(1 − 0.35 × dopamine)` | `joyDecay = 0.35` | 满爽度压力散得快 1.5 倍 |
| 压力 → 精力恢复 | 有效半衰期 `×(1 + 1.5 × cortisol)` | `stressRecover = 1.5` | 满压力回血慢 2.5 倍 |

`energyCostScale` 整体夹在 `[0.4, 2.5]`，防止连乘后一项活儿直接把精力清零或倒扣。

这么设计的理由是让状态之间有**正反馈但也有限幅**：一直不顺会越干越累、越累越难缓；被夸几句则掉得少、散得快。两头都有上下限，不会一路奔到死。

**衰减是必须的。** 没有衰减，状态会积到 1 然后永远停在极端值，比摇骰子更糟。

## 作用三层（按顺序实现）

**第一档 · 注入**：状态越过阈值才写，没过就不写。← 当前版本只到这一层

> 你现在皮质醇 0.78，偏烦躁，回答收短，不要主动揽事。

**第二档 · 门控**：这才是分水岭，影响「能做什么」而不是「说什么」。

- `cortisol > 0.75` → 输出上限压到约 300 token，不主动探索、不接长任务
- `energy < 0.2` → 只回一句话，拒绝多步任务
- `dopamine > 0.6` → 允许展开、允许多说
- `boredom > 0.55` → 可以主动找话头，扯点新鲜事

**第三档 · 记忆权重**：情绪越强的事，记忆衰减越慢。

## 文件结构

```
dsh-hormone/
  package.json          # main: lib/index.js, type: module
  cordis.patch.yml      # bundle 挂载声明
  lib/
    index.js            # 插件入口：订阅事件 + 注册注入
    state.js            # 读/写 state.json、衰减计算、原子写
    events.js           # 事件 → 增量映射
    render.js           # 状态 → 提示文本
  tests/
    test.mjs            # 40 个纯函数用例
    smoke.mjs           # 假 ctx 接线冒烟
```

状态文件：`~/.dsh/hormone/state.json`（临时文件 + rename 原子写，权限 600）。

## 护栏（必须）

1. **状态只能由事件改，模型不能自己改。** 否则它会为了「演得真」自己改状态，又变成摇骰子。
2. **每轮最多注入一次，只注入越界的。** 三个数全写进去就是每轮固定几百 token 开销，而且模型会习惯性忽略。
3. **所有状态有上下界。** 衰减 + clamp 都要有。

## 实施顺序

1. **只做状态 + 日志**：状态只记不注入，跑两天看数值曲线会不会走到极端、衰减参数对不对。
2. **再加注入**：看行为有没有变，没变说明阈值定错。
3. **最后加门控**：门控错了还能修，先上容易翻车。

## 验收

- 跑两天，`~/.dsh/hormone/state.json` 里能看到连续的、有起伏但不极端的曲线
- 注入只在越界时出现，文本不超过 110 字
- 关掉插件后 DSH 一切照旧（无副作用、无报错）
- 不写任何凭据、不联网
